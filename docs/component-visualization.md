# 游戏内组件可视化

## 使用

安装相同版本的 GymCraft 客户端和服务端。管理员将准星指向已经创建环境的 Mob，按 **V** 订阅；再次指向同一对象按 V 取消，指向其他环境实体按 V 切换。**O** 打开不暂停游戏的图层设置界面。按键可以在原版控制设置中重新绑定。

显示、穿墙、标签、角框及各组件图层开关保存在 `gymcraft-client.toml`。A 表示动作，O 表示观测；非空间组件仅提供通用动作状态，菜单和聊天观测首版没有世界标记。

订阅不创建环境，不触发 step/reset，也不占用 gRPC 会话。第一次订阅显示“等待下一次 step/reset”；通过 Python 客户端继续操作环境后出现实际观测。

## 显示语义

- 动作：橙色表示执行中，绿色表示完成，红色表示失败，灰色表示中断。终态图形保留 1.5 秒，最后 0.5 秒淡出。连线只是目标关系，不代表导航路径或视线通畅。
- 观测：标记固定在实际采样位置，HUD 显示采样 tick 和距今游戏时间。对象后来移动、消失或变化不会更新旧快照。下一次观测完整替换旧图层。
- 实体包围框来自采样时的补充调试信息；无法解析实体时使用 protobuf 位置点。结构只显示观测返回的中心坐标。
- 默认穿墙；关闭后遵循深度遮挡。同位置图形优先显示动作颜色，其次为兴趣方块，再次为普通观测，并合并标签。
- 为缓解大量方框淹没画面，观测方框默认只绘制八个角的短线（角框，每棱约 30% 长），关闭后恢复完整线框；观测图形按观察者距离淡出，默认 32 格外完全隐藏、16 格内保持原样，档位可在设置界面切换。动作图形与终态反馈不参与角框与淡出。
- 移动、跳跃显示输入方向；拾取和破坏保留执行前目标；丢弃显示结果中新生成的物品。查不到目标的失败动作仅显示状态与原因。

## 生命周期与限额

每位管理员最多订阅一个环境，多个观察者独立订阅。服务端要求管理员权限、同维度且距离不超过 128 格。离线、越界、跨维度、失去权限或环境关闭会撤销订阅。

reset 保留环境选择，同时提升代次、清空旧图形；同 UUID 的环境删除后重建需要重新选择。订阅标识、环境实例标识、代次与递增序号共同隔离迟到消息。

观测消息最多 512 个图形元素且不超过 128 KiB，优先保留靠近 Agent 的元素。HUD 的“标记 已显示/总数”表示网络快照的截断情况，不包含用户主动隐藏的图层。运行中动作最多 10 Hz 更新；终态不经过位置节流，客户端最多保存 16 条短暂反馈。

## 扩展与维护

在 `VisualAdapters.registerAction` 或 `registerObservation` 注册组件 ID 对应的只读适配器，返回 `VisualElement` 图形列表。渲染器只处理框、点、线和箭头，不需要按组件增加分支；需要设置按钮时同时扩充 `VisualizationConfig.LAYERS`。

适配器禁止调用动作生命周期方法、重新生成观测或加载区块。动作参数/状态来自 `ActionBatchExecutor`；观测来自 `ObservationComposer` 已构建的同一个 protobuf。无订阅者时不采集几何或发送消息。公共模型、订阅和协议不依赖客户端类，也不改变 Python/gRPC 接口。

## 验证

完整测试：`.\gradlew runGameTestServer`。

仅可视化测试（开发启动器要求显式传入主类）：

```powershell
.\gradlew runGameTestServer --args='net.neoforged.fml.startup.GameTestServer --tests gymcraft:visualization_*'
```

测试覆盖消息预算与编解码、乱序/reset/切换缓存、观测快照固定、十二种空间动作转换、权限与双观察者隔离，以及真实 step/reset 的瞬时动作反馈与观测次数。

人工验证时连接专用测试服务器，创建 Agent 并用 V 订阅，再执行 Python step/reset；检查线框、穿墙切换、第三人称、GUI 缩放、图层持久化和取消后清理。
