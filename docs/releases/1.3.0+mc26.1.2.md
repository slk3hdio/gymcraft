# GymCraft 1.3.0+mc26.1.2

本版本新增环境场景存档、Agent 可视化、单区块采矿任务和 MCP 交互入口，并重构 Python LLM 工具包与 gRPC 空间描述。升级时请同步更新模组和 Python 客户端；本版本包含接口变更，旧客户端与新模组不兼容。

## 新增功能

- 场景保存与加载：`/gymcraft env save` 对当前世界和 agent 保存即时快照；`/gymcraft env load <name> [pos]` 从场景生成 agent，并自动完成首次 reset。内置跑酷、采铁及铁傀儡对抗监守者场景。
- 环境状态基线：reset 恢复区域方块、区域实体和 agent；环境自动强加载所需区块，并跟随 agent，减少区块卸载导致的执行停滞。
- 环境管理界面：Environment Tool 右键 Mob 后可选择环境类型、六方向范围和方块/实体快照开关；默认空区域挂载。
- Agent 可视化：支持订阅环境并查看动作、观测、实际寻路路径和环境边界。
- 新增 `mining` 单区块采矿任务环境，以生存工具链里程碑给予稀疏奖励。
- 新增 `swim_to` 水域导航动作、`health_log` 伤害日志观测，以及 `self.main_hand_item` 主手持物观测。
- 新增 `ListEnvironments` gRPC 接口和 Python `list_environments()`，可查询已存在环境及其连接占用状态。
- 新增 `gymcraft-mcp` 命令：通过 MCP 连接环境、reset、执行动作并主动获取观测。使用 `gymcraft[mcp]` 安装可选依赖。
- reset options 支持 `components` 参数，可在运行时调整导航速度、交互距离及观测数量等组件参数。

## Python LLM 工具包

- 动作和观测采用组件声明式注册，DSL 解析、命令说明、观测解包和 Jinja2 渲染从注册表派生。
- `ContextAssembler` 按 `RenderConfig.feedback_fields` 分配历史反馈与最新状态；模型输入只来自观测，奖励、终止状态和 info 保留在调用返回值中。
- 上批动作的逐项反馈由观测 header 的 `last_actions` 提供；chat 与 health_log 按增量语义展示。
- 观测使用表格文本，省略缺席或无有效信息的组件；返回条数由服务端组件参数控制。
- 新增 Chat Completions 文本重试封装和并行 LLM 演示。

## 修复与改进

- 修复导航到达目标后持续旋转的问题；`move_to` / `swim_to` 统一把目标修正为方块中心。
- 修复方块观测的区域钳制，并使用贴面空气优先的双优先级 BFS 扫描，避免预算集中消耗在单个方向。
- 修复 GameTest 的聊天缓冲并行污染及采铁工具链固定延迟提前结束的问题，保留完整业务断言。
- 新增 PyPI 自动发布流程：发布 GitHub Release 后，通过类型检查、测试和打包，再以 Trusted Publishing 上传 Python wheel 与 sdist。

## 升级说明

- 模组和 Python 包均升级到 **1.3.0**。不要混用 1.2.x 的客户端或旧生成桩。
- gRPC 的 `info`、`metadata`、`options` 改为 `google.protobuf.Struct`；Python 端直接使用字典，不再调用 `json.loads()` 解包 info。
- Connect 的空间描述改为结构化 protobuf。自定义客户端需使用 `action_space` / `observation_space`，不再读取旧的 `*_space_json` 字段。
- `use_item` 和 `break_block` 移除 `slot_id`，固定使用 agent 当前主手持物。需要切换工具时，先通过菜单动作调整主手装备，再执行使用或挖掘动作。
- wire 类型从 `gymcraft.type_info` 移到 `gymcraft.types`；`ActionDslParser` 改为 `ActionParser`，渲染配置使用 `RenderConfig` 和 `LLMEnvConfig.render`。自定义 LLM 集成需更新导入和构造参数。
- reset options 的 `allow_multiple_actions` 改为整数 `max_actions_per_step`，默认 9，非正数表示不限制。`components` 参数覆盖会跨 reset 保留。
- 在已有 Mob 上挂载环境不会自动 reset 或加载场景；需要场景内容时使用 `env load`。环境 close 不恢复世界，场景和训练痕迹会保留。
- 场景使用 v3 格式（`scenario.nbt` + `region/*.mca`），旧格式文件直接拒绝加载。请在升级前保留旧场景及世界备份，并用相应版本重新导出需要迁移的场景。

## 发布命名

- Release 标题：`GymCraft 1.3.0+mc26.1.2`。
- Git tag：`v1.3.0+mc26.1.2`。
- 模组附件：`gymcraft-1.3.0+mc26.1.2.jar`；校验文件等其他 GitHub Assets 同样带 `1.3.0+mc26.1.2`。
- Python 包：PyPI 发布 `gymcraft==1.3.0`，wheel/sdist 保持标准文件名且不附加 MC 版本，只上传 PyPI。该 Python 版本默认兼容 GymCraft 1.3.0 的所有 MC 适配版本，后续 MC Release 复用同一个 Python 包。

## 安装

发布后可安装与模组对应的 Python 客户端：

```powershell
pip install --upgrade "gymcraft==1.3.0"
# 需要 MCP 入口时安装可选依赖。
pip install --upgrade "gymcraft[mcp]==1.3.0"
```
